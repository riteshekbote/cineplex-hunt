## LEAD 1: GraphQL Introspection Enabled on Production API
**Asset:** `graphql-api.app.cineplex.de`
**Class:** MISCONFIG (GraphQL schema disclosure)
**Evidence:** POST returns 200 with full schema (200+ types, 100+ Query fields, 100+ Mutation fields including `login`, `startBookingProcess`, `updateUserAdminStatus`, `deleteCineplexUser`, `buyVoucher`, `redeemVoucher`). Schema exposes `User` type with PII: `email`, `fullName`, `telephone`, `birthDate`, `street`, `zipCode`, `tickets`, `orders`, `subscriptions`, `invoices`, `vouchers`. Root GET returns 403 (WAF-gated) but GraphQL POST bypasses — WAF method-gate confirmed across 10+ probe cycles.

| # | Gate Question | Answer |
|---|---|---|
| Q1 | In scope? | **YES** — `*.cineplex.de` infrastructure, "All company-owned infrastructure, APIs" per scope.yml |
| Q2 | Attacker reachable? | **YES** — unauthenticated POST to production GraphQL endpoint; no auth required for introspection query |
| Q3 | Real security impact? | **YES** — full schema disclosure enables targeted IDOR/BOLA, mutation abuse, and attack planning; schema exposes 100+ dangerous mutations (login, booking, user admin, voucher, subscription) and PII-exposing queries |
| Q4 | Provable non-invasively? | **YES** — single POST with `{"query":"{__schema{queryType{name}}}"}` returns 200 + JSON schema; read-only, non-destructive |
| Q5 | Genuinely novel/unreported? | **YES** — not on any known-reported list; probe confirms active across 10+ cycles since 2026-09-03; prior triage validated this at 2026-09-04 |
| Q6 | Not on always-rejected list? | **YES** — "GraphQL introspection" not in out-of-scope; not descriptive errors, not SSL, not DoS, not CSRF, not known-vuln-library |
| Q7 | Would a reasonable triager accept it? | **YES** — production GraphQL introspection enabling full API enumeration with 100+ mutations is a well-established reportable finding class |

**Verdict: VALID**

**Proof steps (read-only):**
1. POST `https://graphql-api.app.cineplex.de/` with `Content-Type: application/json` and body `{"query":"{__schema{queryType{name fields{name}}}}"}` — confirm 200 + schema
2. POST same with `{"query":"{__schema{mutationType{fields{name}}}}"}` — enumerate mutation surface
3. POST same with `{"query":"{__type(name:\"User\"){fields{name type{name}}}}"}` — confirm PII field exposure

**Impact:** Full API schema enumeration → targeted IDOR/BOLA on user/ticket/order queries, mutation abuse (booking cancellation, voucher fraud, admin privilege escalation), account takeover via `login`/`createAnonymousUser` mutations
**CVSS 3.1:** 5.3 (Medium) — Confidentiality impact high, but no direct data exfiltration without further exploitation
**Reporting channel:** bugs.olivermaicher.eu — include introspection response snippet (redact PII), WAF bypass via POST method, schema field list
